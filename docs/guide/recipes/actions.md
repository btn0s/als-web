# Mantle, roll, ragdoll and get up

`Character`'s local input adapter maps jump to ALS jump/mantle probing, Shift sprint/roll policy, and ragdoll/get-up binding. Code-driven players increment `player.command.jumpSequence` once per press and return it from `inputSource`; the fixed physics step consumes each changed sequence once. Return `active:false` on focus loss to clear pending edges. Use `player.ragdoll()` for the ragdoll edge; `player.respawn(position)` recreates the capsule and clears actions. [Command](../../../src/app/AlsPlayer.ts), [input bridge](../../../src/als/AlsCharacter.hooks.ts), [action tests](../../../src/als/AlsCharacter.hooks.test.ts).

Mantle and roll use authored clips, root motion and notify gates. The local `Character` creates the Rapier mantle adapter and montage bridges; invoke actions through its input route instead of setting `locomotionAction` directly. [Character mount](../../../src/app/Character.tsx), [mantle settings](../../../src/als/Settings/AlsMantlingSettings.ts), [rolling implementation](../../../src/als/AlsCharacter_Actions.ts). `ragdollRef` exposes `StartRagdolling()` and `StopRagdolling()` for a game action policy; get-up is selected by the stop lifecycle. [Ragdoll handle](../../../src/engine/rapierAlsRagdoll.ts), [ragdoll hook](../../../src/app/useAlsRagdoll.ts). Remote action events are cosmetic; see [remote](remote.md).

The public code-input contract currently exposes jump but no explicit roll or mantle request field. The built-in input path applies its Shift roll policy and automatic mantle probe. A controller that needs explicit roll/mantle activation must integrate at the internal action bridge in `src/als/AlsCharacter.hooks.ts` and `src/als/AlsCharacter_Actions.ts`; it cannot produce those actions by assigning `locomotionAction`. For ragdoll/game get-up, call `ragdollRef.current?.StartRagdolling()` and `ragdollRef.current?.StopRagdolling()`.
